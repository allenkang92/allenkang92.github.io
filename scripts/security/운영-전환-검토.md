# GitHub Pages 의존성 전환 검토

이 문서와 [워크플로 예시](pages-workflow.example.yml)는 **비활성·미배포 검토 자료**다. 예시 파일은 `.github/workflows` 밖에 있고 게시 작업도 `false` 조건으로 막혀 있다. 복사, 조건 변경, 게시 원본 전환 또는 배포는 이 검토에 포함되지 않는다. 공개 사이트의 의존성이 바뀌었다는 뜻도 아니다.

## 현재 상태와 변경 영향

- 2026-11-12에 확인한 Pages 게시 원본은 `main`의 루트이며, [마지막 성공 실행](https://github.com/allenkang92/allenkang92.github.io/actions/runs/42814671206)의 커밋은 `0525968c0aa56d5bc61480fcd1b2d0ed8f0dabb2`이다. 확인 이후 상태는 바뀔 수 있다.
- 마지막 실행 로그에는 `github-pages` 232가 표시됐다. 별도 후보의 잠금 파일은 `github-pages` 233과 다른 의존성을 선택한다. 둘은 서로 다른 빌드 환경이다.
- 게시 원본을 Actions로 전환하면 모든 방문자가 받는 정적 산출물의 생성 방식이 바뀐다. 글·검색·피드·사이트맵·이전 주소·자산 버전·댓글 연결이 영향 범위이며, 별도 데이터베이스 마이그레이션은 확인되지 않았다.
- [GitHub의 게시 원본 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)에 따라 사용자 지정 워크플로를 사용하려면 게시 원본 설정이 필요하다. 기존 원본을 전환하는 동작 자체도 운영 변경이다.

## 예시의 의도

- 수동 실행 이벤트만 정의하고, 소스 확인은 자격 증명 지속을 끈다. 실제 게시 작업은 `false` 조건으로 비활성화돼 있다.
- 빌드 작업에는 `contents: read`만 두며, 후보 `Gemfile`과 잠금 파일을 `BUNDLE_GEMFILE` 및 고정 모드로 선택한다. Python·Node·Ruby 의존성, 기능 검사, Pages 빌드, 통합 검사 후 산출물을 보관한다.
- 실제 전환을 검토할 경우 게시 작업에만 `pages: write`, `id-token: write`와 `github-pages` 환경을 사용하며 빌드 성공에 의존하도록 구성한다. 권한과 환경 요건은 [GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 따른다.
- 빌드 시험은 `pages-candidate-build`, 비활성 게시 작업은 `pages` 동시 실행 그룹을 사용한다. 실제 전환 전에는 다른 게시 워크플로와 그룹 충돌·대기열 정책을 검토해야 한다. `cancel-in-progress: false`여도 새 요청이 기존 대기 중 실행을 대체할 수 있다. [동시 실행 안내](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)
- `JEKYLL_BUILD_REVISION`에 워크플로가 빌드하는 커밋을 전달한다. 로컬에서는 시험용 값이 검색 스크립트와 CSS 자산 주소에 반영되는 것을 확인했으나 실제 Actions에서는 미검증이다.
- 액션 참조는 2026-11-12에 각 원본 저장소의 릴리스 태그가 가리킨 전체 커밋으로 고정했다. 이는 태그 이동 위험을 줄이지만 모든 공급망 위험을 없애지는 않는다. 활성화 전에 버전·취약점·러너 호환성을 다시 확인한다. [GitHub 보안 안내](https://docs.github.com/en/actions/reference/security/secure-use)

## 확인된 범위와 남은 검증

- [x] macOS 격리 환경에서 후보 설치와 Pages 빌드, 통합 테스트 23건 및 생성물 검사.
- [x] 로컬 후보 `github-pages build`에서 `safe` 설정과 플러그인 허용 목록 적용을 확인.
- [x] 현재 루트와 `/blog` 하위 경로의 주요 링크·이전 주소·검색·피드 관련 기존 통합 검사.
- [ ] Linux의 깨끗한 환경에서 고정 잠금 설치, 네이티브 라이브러리 감사 및 전체 빌드·시험.
- [ ] GitHub Actions 러너에서 이 예시의 의존성 설치, `github-pages build`, 자산 revision과 산출물 업로드 확인. 이 예시는 아직 Actions에서 실행하지 않았다.
- [ ] 실제 관리형 빌드와 후보의 URL·리다이렉트·검색 인덱스·피드·자산·댓글·오류 페이지를 비교하고 차이를 검토.
- [ ] 게시 원본 전환 시 환경 보호 규칙, 권한, 산출물 보존, 공개 사이트 모니터링과 복구 경로 확인.
- [ ] 새로 잠긴 Ruby 및 네이티브 라이브러리의 보안 권고와 액션 참조를 재검토. 과거 OSV 결과는 지속적인 안전 보증이 아니다.

## 전환 및 복구 검토

전환은 단일 공개 사이트에 영향을 주므로 현재 근거만으로 부분 사용자 대상 시험이나 자동 복구를 보장할 수 없다. 준비 단계에서 현재 Pages 원본 설정, 정상 빌드 커밋, 빌드 로그와 산출물을 기록하고, 실제 전환 전 위 검증 항목을 완료해야 한다. 작업자가 `main`에 반영된 전체 변경과 새 의존성 파일을 함께 검토할 필요도 있다.

게시 실패, 주요 URL 오류, 검색·피드·리다이렉트 또는 자산 로딩 회귀가 확인되면 전환을 중단하고 마지막 정상 상태로 복구한다. 가능한 복구 후보는 기존 브랜치 기반 게시 원본으로 돌아가거나 검증된 이전 산출물을 다시 게시하는 것이다. **어느 경로가 실제로 작동하는지, 전환에 걸리는 시간과 환경 보호 규칙의 영향은 아직 시험하지 않았다.** 원본을 `main`으로 되돌려도 그 시점의 `main` 내용이 자동으로 이전 커밋이 되지는 않는다. 필요하다면 별도 복구 브랜치 사용을 사전에 검증해야 하며, 강제 푸시나 기존 사용자 변경 삭제를 전제로 하지 않는다.

현재 판정: **운영 전환 보류**. 이 예시를 검증·활성화하거나 공개 게시 원본을 변경하지 않았다.
