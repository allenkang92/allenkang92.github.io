# 기술 블로그 사례와 기능 보강 검토

## 연구 질문

현재 블로그의 글 찾기, 긴 글 읽기, 코드 활용, 검색·공유 표현에서 실질적으로 보강할 부분은 무엇인가?

## 중요성

정적 사이트와 기존 콘텐츠 규모에 맞는 기능을 선택해야 독자가 글과 예제를 사용하기 쉽고, 운영자는 불필요한 계정·개인정보 처리 부담을 피할 수 있다.

## 방법·근거 범위

기존 세 사이트 비교에 더해 공개 기술 블로그와 Jekyll 테마의 화면·문서, Google·Schema.org·W3C·MDN·Chrome 공식 문서를 2026-11-13에 확인하고 로컬 생성물과 대조했다. 목적에 따라 고른 사례이며 블로그 전체의 대표 표본이나 사용자 실험은 아니다.

## 핵심 근거

- 로컬 생성물의 CSS 글 37개, HTML 글 10개, 웹 접근성 글 6개 코드 블록에는 복사 전용 버튼이 없었다. [Josh W. Comeau의 코드 글](https://www.joshwcomeau.com/css/anchor-positioning/)과 [Minimal Mistakes 설정 문서](https://jekyllnet.github.io/minimal-mistakes/docs/configuration/)에는 코드 복사 기능이 있다. 사례는 기능의 존재를 보여주며 효과를 증명하지 않는다.
- [Clipboard API 문서](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)는 보안 컨텍스트와 거부 가능성을 설명한다. [Chrome 복사 버튼 가이드](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-components/copy-button)와 [W3C 상태 메시지](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)는 조작 및 결과 안내 설계에 참고할 수 있다.
- 생성된 글의 구조화 데이터에는 공통 사이트 로고가 이미지로 들어간다. [Google Article 안내](https://developers.google.com/search/docs/appearance/structured-data/article)는 글을 대표하는 관련 이미지를 권장한다.
- 성과 상세는 교육·경력·자격 등의 분류 페이지인데 기존 구조화 유형은 `BlogPosting`이었다. [Schema.org](https://schema.org/BlogPosting)는 이를 블로그 글로 정의하며, [WebPage](https://schema.org/WebPage)는 일반 웹페이지 유형이다.

## 상충하는 근거

코드 복사는 재사용을 돕는 반면, 한 페이지에 37개 버튼이 생기면 시각·키보드 탐색 부담이 늘 수 있다. 사이트 로고는 공유 미리보기에서 유용할 수 있지만 글의 내용별 대표 이미지와 목적이 다르다. 태그와 이메일 구독을 제공하는 사례도 있으나 현재 19개 글 중 태그가 있는 글은 한 개뿐이며 구독은 추가 개인정보 처리와 운영이 필요하다.

## 발견

기존 사이트에는 검색·카테고리·시리즈·목차·Atom 피드가 이미 있다. 반복 코드 예제의 복사 지원과 성과 페이지의 검색·공유 메타데이터는 보강 가능한 영역이다.

## 해석

코드 복사가 이 블로그에서 사용성이나 재방문율을 높인다는 측정은 없다. 성과 상세를 `WebPage`로 표현하는 것은 현재 콘텐츠 성격에 따른 해석이다. 올바른 마크업이 검색 결과 표시나 순위 개선을 보장하지는 않는다.

## 한계

공개 화면 관찰과 로컬 생성물 검토에 한정되며 실제 독자 수요, 검색 노출, 모바일 실기기·스크린리더 경험은 측정하지 않았다. 모든 글의 학술적 정확성과 모든 외부 서비스를 검증한 것은 아니다.

## 제품·설계·운영 함의

- **제품·설계:** 코드 복사 시 코드 내용만 보존하고, 키보드 접근·결과 안내·거부 시 수동 선택을 제공한다. 반복 버튼의 밀도와 이름을 확인한다.
- **검색 표현:** 성과 유형은 내용에 맞게 표현하고, 공통 로고를 Article 대표 이미지로 쓰는 부분은 공유 미리보기 손실 여부를 포함해 별도 검토한다.
- **운영:** 태그 전용 탐색과 이메일 구독은 현 규모에서 우선 도입할 근거가 부족하다. GA 설정은 사용자가 선택한 기존 상태를 유지한다.

## 제안되는 다음 단계

코드 복사 기능과 성과 메타데이터 변경은 로컬에 구현했다. 실제 공유 서비스에서의 표시와 실제 독자 사용성은 확인하지 않았다. 글별 대표 이미지 문제는 Open Graph 공유 이미지와 Article JSON-LD를 분리할 수 있는지, 기존 배포 환경과 검색 결과에 미치는 영향을 확인한 뒤 판단한다.

성과 제목·설명에 `&`를 넣은 합성 자료에서는 HTML 메타데이터가 정상 표시되지만 JSON-LD 문자열에는 문자 참조가 남는 한계를 확인했다. 기존 SEO 플러그인에도 같은 현상이 있었다. 현재 다섯 성과 제목·설명에서 해당 문자는 확인되지 않았으며, 관리형 Pages에서 범용 HTML 문자 참조 해독 필터를 찾지 못해 부분 치환은 적용하지 않았다.
