# 블로그 기능·보안 검수와 참고 근거

기준일: 2026-11-10. 이 문서는 로컬 작업과 검수 범위를 기록한다. 커밋·배포 여부는 Git 상태와 실제 Pages 배포에서 별도로 확인한다.

## 질문과 방법

19개 글을 가진 정적 연구 블로그에서 독자가 글을 찾고, 순서대로 읽고, 도구를 사용하고, 구독하는 데 필요한 기능을 확인했다. 저장소 코드와 Jekyll 생성물, 주요 브라우저 동작을 검토하고, 공개 블로그 사례 및 공식 문서를 비교했다. 사례 비교는 소수 사이트의 공개 화면 관찰이며 독자 이용률이나 기능 효과를 측정한 연구가 아니다.

## 외부 사례와 판단

- [Lilian Weng](https://lilianweng.github.io/)은 글 목록·검색·태그를, [Andrej Karpathy](https://karpathy.github.io/)는 날짜와 요약 중심 목록을, [colah](https://colah.github.io/)은 주제별 글 묶음을 제공한다. 이들은 가능한 탐색 패턴의 사례이며 특정 기능의 효과를 증명하지 않는다.
- 이 사이트에는 검색, 카테고리, 시리즈, 목차와 이전·다음 글이 이미 존재한다. 기존 기능의 연결과 상태를 바로잡는 것을 우선하고, 별도의 회원 기능이나 추천 알고리즘은 추가하지 않았다.
- [jekyll-feed 공식 문서](https://github.com/jekyll/jekyll-feed)는 Atom 피드와 자동 발견 메타데이터를 제공한다. 기존에 생성되던 피드에 발견 메타데이터와 구독 링크를 연결했다. 피드 리더 앱별 동작은 별도 확인이 필요하다.
- [W3C의 페이지 내 탐색 안내](https://www.w3.org/WAI/tutorials/page-structure/in-page-navigation/)는 제목 ID와 목차가 긴 페이지의 탐색 및 특정 구간 참조를 도울 수 있다고 설명한다. 해당 안내는 진행 중인 초안이며 사용자 실험의 대체 근거는 아니다.

로컬은 Ruby 2.6.10, github-pages 231, Jekyll 3.9.5, Nokogiri 1.13.10이다. 같은 날짜에 확인한 GitHub Pages 공개 목록은 각각 Ruby 3.3.4, github-pages 232, Jekyll 3.10.0, Nokogiri 1.16.7을 명시했다. 공개 목록과 로컬 목록의 이름이 겹치는 46개 패키지만 따로 조회하면 Nokogiri에 권고 식별자 18개가 일치한다. 이는 공개 목록에 없는 간접 의존성과 실제 개별 빌드의 설치 내역을 확인한 결과가 아니다. 예를 들어 [Nokogiri XML 정규화 권고](https://github.com/sparklemotion/nokogiri/security/advisories/GHSA-wx95-c6cv-8532)는 특정 정규화 실패 시 오류를 처리하는 기능에 관한 것이다. 저장소의 직접 코드 검색에서는 해당 기능이나 SAML 사용을 찾지 못했지만 플러그인의 모든 간접 호출을 배제한 것은 아니다. 일부 다른 권고는 JRuby 또는 번들된 XML 라이브러리에 한정된다. [GitHub Pages는 정적 파일을 제공하므로](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) 이 문제를 방문 요청마다 루비 서버가 실행되는 상황으로 간주하지 않는다. 빌드 환경과 산출물에 대한 영향은 권고별 입력 경로를 따로 검토해야 한다.

기존 관리형 빌드와 로컬 Ruby 2.6의 버전 제약 때문에 권고된 모든 수정 버전을 단순 적용할 수 있다고 확인되지 않았다. 의존성 변경이나 배포 방식 전환은 하지 않았으며, 호환성을 검증한 대안이 필요하다. 열린 GitHub 알림 0건은 이 별도 대조를 대신하지 않는다.

`concurrent-ruby` 1.3.7을 임시 디렉터리에 설치하고 잠금 파일 사본의 해당 버전만 바꾼 실험에서는 실제 버전 로드, 의존성 확인, Jekyll 빌드와 생성물 통합 테스트 21건이 통과했다. 그러나 정식 의존성 갱신은 기존 `ffi`의 플랫폼별 루비 버전 제약 충돌로 실패했다. 따라서 이 실험은 깨끗한 의존성 재해석이나 공개 빌드 적용의 안전성을 증명하지 않으며, 원본 잠금 파일과 저장소 의존성은 변경하지 않았다.

별도 임시 디렉터리에 Ruby 3.3.13과 `github-pages` 233을 설치하고 의존성을 정상 재해석한 후에도 Jekyll 빌드와 통합 테스트 21건이 통과했다. 생성물 검사는 HTML 57개, 내부 주소 1,248개, 문서 내 이동 41개를 확인했다. 이때 선택된 `nokogiri`는 1.19.7, `rubyzip`은 3.7.0, `concurrent-ruby`는 1.3.8이었다. 후보 잠금 파일에 포함된 RubyGems 패키지 100개를 OSV에 대조한 결과 일치하는 권고가 없었고, 100개 응답과 추가 페이지 유무를 확인했다. 이는 조회 시점의 RubyGems 버전 대조 결과이며 네이티브 라이브러리까지 포함해 모든 보안 결함이 없다는 뜻은 아니다.

같은 개발 모드의 기존 생성물과 후보 생성물은 모두 103개 파일이며 추가·삭제된 경로는 없었다. 38개 파일에 바이트 차이가 있었으며, Jekyll·SEO 태그 버전과 자산 버전 표기, 피드 생성 시간 차이 등이 포함된다. 검색 인덱스 30개 항목과 사이트맵, 피드 글 10개의 주요 내용은 같았다. 이전 주소 이동 20개도 기존 생성물과 같았다. 이 비교는 모든 표시나 외부 연동이 동일하다는 증명은 아니다.

## Analytics와 남은 제한

- 실제 블로그 GA4 스트림에서 향상된 측정과 사이트 검색이 활성화되어 있고 URL 쿼리 키 가림은 비활성화되어 있음을 확인했다. 검색어가 `q`에 들어가는 구조이므로 개인정보를 포함한 검색어가 Analytics로 전송될 가능성이 있다. 실제 전송 패킷, 과거 수집 내용과 저장 범위는 확인하지 않았다. [Google 향상된 측정 문서](https://support.google.com/analytics/answer/9216061), [데이터 가림 문서](https://support.google.com/analytics/answer/13544947).
- 사용자는 분석과 현재 설정의 유지를 선택했다. 이에 따라 GA 속성 설정은 변경하지 않았다. 검색어별 통계의 유지와 개인정보 위험은 함께 남는다.
- 정적 검사에서 생성 HTML 전체와 내부 URL, 검색 인덱스, Atom 및 사이트맵을 확인했다. 외부 링크는 점검 도구가 확인한 범위로 한정되며, 모든 글의 학술적 주장, 모든 기기·스크린리더, 모든 외부 서비스 장애를 전수 검증한 것은 아니다.
